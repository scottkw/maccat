# Milestone v0.47.0 — Audit Report

**Milestone:** Catalog Retention & Sync
**Audited:** 2026-06-13
**Status:** ✅ PASSED

## Summary

This milestone reworked `update-list.sh`'s archive/retention/git logic so that every run keeps
only the newest catalog **per machine (hostname)** in the targeted location's main folder, moves
older per-machine catalogs to that location's `archive/`, **hard-deletes** archive catalogs older
than 30 days, and stages every resulting change (additions, moves, deletions) in a single git
commit so all machines converge. One phase (Phase 6), all 6 requirements satisfied, verification
passed.

## Integration & E2E (single-phase milestone)

Cross-phase integration is trivial here — one phase modifying the existing flow. Verified during
phase verification:
- The two new functions (`retain_newest_per_host`, `prune_old_archives`) replace
  `archive_old_catalogs` and are wired into the main block in the corrected order:
  `git_pull → set OUTPUT vars → generate_catalog → retain_newest_per_host → prune_old_archives →
  (AUTO_COMMIT) git_commit_and_push`. Generate runs BEFORE retention, so the just-written catalog
  is the newest and is never archived.
- `generate_catalog` and the 13 collector functions from v0.46.0 are unchanged.
- `git_commit_and_push` stages `git add -A "${TARGET_LOCATION}/"` (scoped to the targeted location;
  captures adds + moves + deletions), gated by `AUTO_COMMIT`.
- `zsh -n update-list.sh` exits 0.

## Safety (data-loss review)

The code review specifically audited the destructive operations and found **0 critical** issues.
Verified by construction: only files matching `mac-software-list-[*]-*.txt` inside the targeted
location (and its `archive/`) are ever moved or `rm`'d; the newest-per-host file is never archived;
tied-newest files are kept; unparseable/missing timestamps are skipped (never deleted); the
non-targeted location is never touched; `git add -A` is scoped to the target directory only. The
three review warnings (unchecked `mv`/`rm` exit codes, and a `--no-commit` hint that used
`git add .`) were fixed and re-verified.
