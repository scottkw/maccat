## Cross-Phase Integration — 5/5 (verified inline by reading update-list.sh)

> The spawned integration-checker run died on a transient API socket error; the
> integration verification below was performed inline against the source.

1. **Shared map TSV contract** — Phase 8 (`resolve_machine_label` L419/445,
   `upsert_machine_label` L341) and Phase 9 (`rename_machine` L532, L678) both
   read `machine-labels.tsv` via `IFS=$'\t' read -r … || [[ -n … ]]` and write
   it via the same `.tmp`+`mv` atomic pattern. A rename cannot corrupt a
   normal-run map write and vice versa. ✓ (REN-02, MID-04)
2. **Label-parsing consistency** — the `${filename#*\[}` / `${tmp%\]-*}` idiom is
   identical in `rename_machine` (L561/640), `retain_newest_per_host` (L806), and
   `prune_old_archives` (L824). A space-containing label round-trips through
   filename generation → retention grouping → rename matching. ✓ (MID-01, REN-01)
3. **`validate_machine_label` reuse** — single definition (L118), reused by the
   `--machine` flag (L192), `resolve_machine_label` create-new (L488), and
   `rename_machine` NEW label (L610). No divergence. ✓ (MID-03, REN-01)
4. **Flag/mode interactions** — all six flags parsed in one `parse_arguments`;
   `--rename`+`--machine` combination explicitly rejected (L211). ✓
5. **Rename short-circuit ordering** — main block L2285-2289: `git_pull →
   rename_machine → exit 0`, strictly before `get_target_location`,
   `resolve_archive_retention`, `resolve_machine_label`, and catalog generation/
   prune. Rename never triggers catalog gen or hard-delete. ✓ (REN-01, REN-02)

## E2E Flows — 4/4

- **Fresh machine:** no saved label → menu prompt → catalog named `[label]` → map upserted → committed. ✓
- **Subsequent run:** hostname found in map → auto-resolve, no prompt. ✓
- **Rename:** pick OLD (from map ∪ filename segments) → validated NEW → rename across all 4 dirs → map updated → single commit/push; no-match → warn + exit (no map change, no commit). ✓
- **Retention with labels:** `--archive-days N` prunes label-named archive files correctly (shared `[...]` parser). ✓
