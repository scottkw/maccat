The parametrized test is driven by EXPECTED_STEMS (17 items). The three that need skipping:
  "homebrew-packages"          — brew output now versioned; golden is name-only
  "setapp-applications"        — plist version added; golden is name-only
  "web-installed-applications" — plist version added; golden is name-only

Existing pytest marks in use: @pytest.mark.zsh_parity, @pytest.mark.skipif

Relevant pytest skip mechanisms:
  pytest.mark.skip(reason="...") — unconditional skip
  pytest.mark.xfail(reason="...", strict=False) — expected failure (shows 'x' not 'F')
  pytest.mark.parametrize with indirect marks via pytest_collection_modifyitems hook — complex

RECOMMENDATION: Use pytest.mark.xfail(reason=..., strict=False) applied per-stem via a
SKIP_STEMS mapping at module level + pytest_configure or via a conftest.py mark. The simplest
pattern that keeps test_golden_parity.py self-contained:

  XFAIL_STEMS: dict[str, str] = {
      "homebrew-packages": (
          "Phase 22 versioned output intentionally diverges from frozen zsh golden "
          "(ZSH-02). Parity suite retired in Phase 23."
      ),
      "setapp-applications": (
          "Phase 22 versioned output intentionally diverges from frozen zsh golden "
          "(ZSH-02). Parity suite retired in Phase 23."
      ),
      "web-installed-applications": (
          "Phase 22 versioned output intentionally diverges from frozen zsh golden "
          "(ZSH-02). Parity suite retired in Phase 23."
      ),
  }

  Then in test_section_parity, at the top of the function body:
      if section_stem in XFAIL_STEMS:
          pytest.skip(XFAIL_STEMS[section_stem])

  Using pytest.skip() inside the function body produces a SKIPPED result (not xfail),
  which is clean and clearly visible. This is the simplest approach that avoids
  conditional mark injection complexity.
