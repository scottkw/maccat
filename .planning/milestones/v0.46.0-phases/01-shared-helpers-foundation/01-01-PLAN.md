<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| json_get file parameter | Local filesystem path provided by caller (Phase 2–4 collectors). The file content is user-owned config/manifest data on the local machine. No network I/O. |
| emit_item / flush_section output | Lines flow from caller-supplied name/version/id strings into _section_lines and then into OUTPUT_FILE. The OUTPUT_FILE is a git-committed catalog — its contents become permanent history. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | flush_section → OUTPUT_FILE | mitigate (design intent) | FMT-03 design constraint: emit_item receives only (name, version, id) as discrete arguments from callers; it never reads raw JSON blobs, env vars, headers, or URL strings. The helper has no access to secrets — the caller is responsible for extracting only the safe scalar before calling emit_item. This must be enforced by every Phase 3 (MCP) collector: extract name+transport, call emit_item; do NOT pass full URL strings or env values as the "id" argument. Document this contract in Phase 3 planning. |
| T-01-02 | Information Disclosure | json_get → stdout | mitigate (by design) | json_get extracts exactly one field by key path and echoes it to stdout. It does not enumerate sibling keys, log the full file, or write to OUTPUT_FILE. Callers in Phase 3 must request only non-secret fields (e.g. "name", "command", "type") — never "env", "headers", or "args". This is a caller responsibility enforced by Phase 3 plans, but the helper's single-key contract makes leakage structurally hard. |
| T-01-03 | Tampering | _section_lines global array | accept | _section_lines is an in-process global reset by flush_section after each section. Within a single script run there is no persistence threat. The reset discipline (collectors call _section_lines=() at top) prevents cross-section pollution; documented in flush_section comment block. |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | Phase 1 installs zero packages. No package manager is invoked. The slopcheck gate does not apply. |
</threat_model>
