# Requirements: Mac Software List Generator — v0.47.0 Catalog Retention & Sync

**Defined:** 2026-06-13
**Core Value:** A single run produces one complete, restorable snapshot of a machine's software *and* tooling extensions — accurate enough to rebuild the environment from, degrading gracefully when any source isn't installed.

## v1 Requirements

Requirements for this milestone. They change `update-list.sh`'s archive/retention behavior so the main location folders stay lean (newest-per-machine only), the archive self-prunes at 30 days, and every machine converges via git. "Per machine" means grouped by the hostname embedded in `mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt`.

### Retention

- [x] **RET-01**: On every run, the targeted location's main folder (`personal/` or `office/`) retains only the **newest catalog per machine** (by the filename's hostname + timestamp); every older catalog for each hostname is moved to that location's `archive/` folder
- [x] **RET-02**: On every run, catalog files in the targeted location's `archive/` folder whose filename timestamp is **older than 30 days** are **hard-deleted** from disk
- [x] **RET-03**: Retention (RET-01) and pruning (RET-02) are scoped to the **targeted location only** — a `--personal` run touches only `personal/` and `personal/archive/`; a `--office` run touches only `office/` and `office/archive/`
- [x] **RET-04**: Retention and pruning **never abort the run** — an empty folder, a missing `archive/` directory, or a catalog filename whose timestamp can't be parsed is handled gracefully (warn-and-continue), and the new catalog is still produced

### Sync

- [x] **SYNC-01**: The existing git commit/push cycle stages and syncs **all** working-tree changes in the targeted location — the newly generated catalog (addition), the catalogs moved into `archive/` (renames), and the catalogs removed by the 30-day prune (deletions) — in a single commit, so every machine that pulls converges on the same retained set
- [x] **SYNC-02**: `--no-commit` still skips the commit/push entirely (the retention/prune disk operations still run; only the git step is skipped)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Rewriting `git history` to purge already-committed old catalogs | Out of scope and destructive; the 30-day prune applies going forward via `git rm`. Past commits keep history. |
| Pruning/retention across BOTH locations on a single run | Scoped to the targeted location by decision; a run only manages what it targeted. |
| "Single newest overall" retention (one file total) | Rejected in favor of newest-per-machine, matching the "one snapshot per machine" core value. |
| Configurable retention window / configurable "keep N per machine" | Fixed at newest-1-per-machine + 30-day archive prune this milestone. |
| Cross-platform support (Linux/Windows) | Tool is macOS/Zsh-only by design (BSD `date -v`, `/Applications`). |
