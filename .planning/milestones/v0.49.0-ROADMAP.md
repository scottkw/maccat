## Phase Details

### Phase 10: Computer-Folder Identity Foundation

**Goal**: The folder name is the machine identity — every new catalog is named after its folder, and the hostname→computer map records which folder this Mac uses
**Depends on**: Nothing (foundation for Phases 11 and 12)
**Requirements**: CID-01, CID-02, CID-03
**Success Criteria** (what must be TRUE):

  1. A catalog saved into folder `Example Computer` is named `mac-software-list-[Example Computer]-YYYYMMDDHHMMSS.txt` — no raw hostname in the name
  2. A computer name containing `/`, `[`, `]`, tab, newline, or leading/trailing whitespace is rejected; names with spaces, apostrophes, letters, digits, `-`, `_`, `.` are accepted
  3. The validation rule is a single shared implementation used by both the flag path (fail-fast, exit 1) and the interactive path (re-prompt, no exit)
  4. After selecting computer `X`, `machine-labels.tsv` contains an entry mapping this Mac's hostname to `X`, and a subsequent run reads that entry to mark `X` as the default

**Plans**: 1 plan
Plans:

- [x] 10-01-PLAN.md — Rename validation helpers, wire CURRENT_MACHINE from TARGET_LOCATION (folder identity), update upsert and map header

**Testing constraint (all phases):** `update-list.sh` is destructive to run. Verify with `zsh -n` (syntax check), source/grep assertions against the script text, and isolated function tests in a `mktemp -d` fixture. NEVER run the script live against the repo's real `personal/`/`office/` trees.

### Phase 11: Computer Selection & CLI

**Goal**: Users select or create a computer from an always-shown menu (with a remembered default) or via `--computer`/alias flags, and can quit any menu cleanly
**Depends on**: Phase 10 (validation helper, map format, folder-as-identity model)
**Requirements**: SEL-01, SEL-02, SEL-03, SEL-04, CLI-01, CLI-02, QUIT-01
**Success Criteria** (what must be TRUE):

  1. Running interactively shows a numbered list of existing computer folders, a "Create new computer" option, and a "Quit" option — every time, no silent auto-selection
  2. The computer this Mac last used is shown with "(this machine — default)" and pressing Enter without typing selects it; a Mac with no remembered computer has no Enter default and must choose explicitly
  3. Choosing "Create new computer" prompts for a name, re-prompts on invalid input without aborting, creates the folder, and uses it for the run
  4. Invalid input at any menu prompt re-prompts rather than exiting with an error
  5. `--computer "Example Computer"` runs non-interactively, selecting or creating that folder without showing the menu; `--personal`, `--office`, and `--machine "X"` work as equivalent aliases
  6. Choosing Quit at the computer selection menu exits cleanly (status 0) with no catalog written and no git commit made

### Phase 12: Computer Rename

**Goal**: Users can rename a computer (folder) with all its catalog files updated to match, in a single git commit
**Depends on**: Phase 10 (map format, validation), Phase 11 (Quit option in picker)
**Requirements**: RNM-01, RNM-02, RNM-03
**Success Criteria** (what must be TRUE):

  1. `--rename` shows a numbered menu of existing computers plus Quit; choosing a computer then prompts for the new name (validated, re-prompts on invalid); Quit exits cleanly with nothing changed
  2. After rename with the default "rewrite" option, every catalog inside the folder (main + archive) has its `[oldname]` segment replaced with `[newname]`, and the folder itself is renamed; choosing the opt-out leaves existing filenames with the old label while the folder takes the new name going forward
  3. The hostname→computer map entries are updated to the new folder name, and the folder move, any filename rewrites, and the map update are staged and committed in a single git commit (or printed as manual instructions when `--no-commit` is set)
  4. Attempting to rename a computer to its current name, or naming a computer that does not exist, warns and exits without creating a commit or moving any files
