# Roadmap: Mac Software List Generator — Extension Cataloging

## Overview

This milestone extends the working single-file Zsh script `update-list.sh` so a single run
also catalogs the extensions, plugins, MCP servers, and skills/agents of four AI coding CLIs
(Claude Code, Codex, OpenCode, Gemini), two editors (VS Code, Cursor), and two browsers
(Chrome, Firefox). The build follows the research-verified order: a small **shared-helpers
foundation** comes first (it is the only cross-collector dependency), then the otherwise
**independent collectors** are grouped by source type (editors, AI CLIs, browsers) and built
in order of rising complexity, and finally an **integration phase** wires every collector into
`generate_catalog` and runs the two non-negotiable gates — zero secret leakage and a
diff-empty determinism check. The architecture is mirrored, not refactored: each collector
checks availability, appends to the global `OUTPUT_FILE`, and degrades gracefully when its
source is absent.

## Phase Details

### Phase 1: Shared Helpers Foundation
**Goal**: A reusable, dependency-free helper layer exists that every later collector uses to read JSON, resolve Chrome names, emit a uniform item line, and produce stably-sorted output
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: FMT-01, FMT-04
**Success Criteria** (what must be TRUE):
  1. `json_get <file> <key>` returns the correct scalar via jq when present, falls back to plutil (always present at /usr/bin/plutil since macOS 10.4), and returns empty string (not null, not abort) when the key is absent — plutil is the terminal fallback; python3 is NOT in the chain (it is an xcrun stub on clean macOS that blocks the script with a GUI dialog)
  2. `chrome_ext_name <manifest>` resolves a `__MSG_*__` placeholder to its real name via `_locales/<default_locale>/messages.json` (case-insensitive key match), and falls back to the 32-char extension ID rather than emitting a blank name
  3. The shared `emit_item` helper produces the uniform line `name (version) [id]`, degrading gracefully under all 7 cases (no version, no id, no name, combinations) so every collector renders identically
  4. `flush_section` sorts items via `LC_ALL=C sort -f -u` before writing to OUTPUT_FILE, deduplicates, and resets the buffer — two consecutive runs on unchanged input produce byte-identical output

### Phase 2: Editor Collectors
**Goal**: A single run produces VS Code and Cursor extension sections in the catalog, read from the editors' `extensions.json` (with CLI as the preferred path when present)
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: VSC-01, CUR-01
**Success Criteria** (what must be TRUE):
  1. Running `update-list.sh` produces a "VS Code Extensions" section listing each extension as `name (version) [id]`, derived from `code --list-extensions --show-versions` or, when the CLI is absent, parsed from `~/.vscode/extensions/extensions.json`
  2. Running `update-list.sh` produces a "Cursor Extensions" section in the same `name (version) [id]` format via the `cursor` CLI or `~/.cursor/extensions/extensions.json` fallback
  3. When an editor is not installed (no CLI and no `extensions.json`), its section is still written with a short "not installed / none found" note and the run continues
  4. Items within each editor section are stably sorted so repeated runs produce identical output

### Phase 5: Integration & Verification Gates
**Goal**: All new collectors are wired into `generate_catalog` in fixed order, and the complete catalog passes the two non-negotiable gates: zero secret leakage and diff-empty determinism
**Mode:** mvp
**Depends on**: Phase 2, Phase 3, Phase 4
**Requirements**: FMT-02
**Success Criteria** (what must be TRUE):
  1. `generate_catalog` calls every collector in fixed order (AI CLIs → editors → browsers) appended after the existing Web-installed block, with the existing sections, archive flow, and git flow untouched
  2. **Secret-leakage gate:** grepping the NEW tooling sections of the generated catalog (from the first new section header to EOF — scoped to avoid false positives from legitimate Homebrew formula names like `libnghttp2`/`httpie` that contain `http`) for `https?://`, `token`, `Bearer `, `key=`, `Authorization`, `sk-`, and `ghp_` returns ZERO hits (scope refined by Phase 5 discuss/research)
  3. **Determinism gate:** two consecutive `--no-commit` runs on an unchanged machine produce identical catalog CONTENT (the timestamp lives only in the filename, not file content) — `diff` of the two outputs is empty across the new sections (firm) and ideally the whole file
  4. **Graceful-degradation verification:** a run on a machine missing some sources (and a run with `jq` removed from PATH) completes without aborting, writing a "not installed / none found" note for every absent source (FMT-02)
