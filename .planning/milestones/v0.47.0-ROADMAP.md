## Phase Details

### Phase 6: Retention & Sync
**Goal**: Every run leaves the targeted location's main folder with exactly one catalog per machine, its archive self-pruned at 30 days, and all changes committed so every machine that pulls converges on the same retained set
**Depends on**: Nothing (continues from v0.46.0 Phase 5 — git/archive flow already in place)
**Requirements**: RET-01, RET-02, RET-03, RET-04, SYNC-01, SYNC-02
**Success Criteria** (what must be TRUE):
  1. After a run on a machine that has two catalogs for the same hostname in `personal/` or `office/`, the main folder contains exactly one (the newest) and the older one is in `archive/`
  2. After a run, any file in `archive/` whose filename timestamp is older than 30 days has been deleted from disk — archive/ holds at most 30 days of history
  3. Running with `--personal` touches only `personal/` and `personal/archive/`; running with `--office` touches only `office/` and `office/archive/` — neither run touches the other location
  4. A run against an empty folder, a missing `archive/` directory, or a catalog with an unparseable timestamp completes successfully and still produces the new catalog (warn-and-continue; no abort)
  5. The resulting git commit includes the new catalog (addition), any catalogs moved to archive (rename/add+delete), and any 30-day-pruned files (deletion) — a pull from another machine converges its working tree to the retained set; `--no-commit` skips the commit entirely while the disk operations still run
**Plans**: 1 plan
