# Requirements: Mac Software List Generator — Extension Cataloging

**Defined:** 2026-06-12
**Core Value:** A single run produces one complete, restorable snapshot of a machine's software *and* tooling extensions — accurate enough to rebuild the environment from, degrading gracefully when any source isn't installed.

## v1 Requirements

Requirements for this milestone. Each adds catalog coverage to `update-list.sh` and maps to a roadmap phase. Per-item detail is **name + version + ID** where each is obtainable; output is appended as new plain-text sections to the existing per-machine catalog file.

### Output Quality (cross-cutting)

- [x] **FMT-01**: Every new catalog item is emitted in a uniform line format `name (version) [id]`, degrading to `name [id]` when no version exists
- [x] **FMT-02**: Each new source degrades gracefully — when its CLI/tool/browser/profile is absent, the script writes a short "not installed / none found" note and continues without aborting
- [x] **FMT-03**: No secrets are ever written to the catalog — MCP server entries capture name + transport/identifier only, never env values, headers, tokens, or auth-bearing URL components (catalog is git-committed and pushed)
- [x] **FMT-04**: Catalog output is deterministic — items within every new section are sorted stably so two consecutive runs with no machine changes produce an empty diff

### Claude Code

- [x] **CC-01**: Catalog installed Claude Code plugins (name + version + ID)
- [x] **CC-02**: Catalog configured Claude Code MCP servers (name + transport only, per FMT-03)
- [x] **CC-03**: Catalog Claude Code skills and subagents present under `~/.claude/`

### Codex

- [x] **CDX-01**: Catalog configured Codex MCP servers (name + transport only, per FMT-03)

### OpenCode

- [x] **OC-01**: Catalog OpenCode plugins from its config
- [x] **OC-02**: Catalog configured OpenCode MCP servers (name + transport only, per FMT-03)
- [x] **OC-03**: Catalog OpenCode agents from its config

### Gemini CLI

- [x] **GEM-01**: Catalog installed Gemini CLI extensions (name + version + ID)
- [x] **GEM-02**: Catalog configured Gemini CLI MCP servers (name + transport only, per FMT-03)

### Editors

- [x] **VSC-01**: Catalog installed VS Code extensions (name + version + ID) via `code --list-extensions --show-versions`, falling back to parsing `extensions.json`
- [x] **CUR-01**: Catalog installed Cursor extensions (name + version + ID) via the `cursor` CLI, falling back to parsing `extensions.json`

### Browser Extensions

- [x] **CHR-01**: Catalog Google Chrome extensions across all profiles (name + version + ID), resolving `__MSG_*` localized names via `_locales/<default_locale>/messages.json` and falling back to the extension ID when a name can't be resolved
- [x] **FF-01**: Catalog Firefox extensions across all profiles (name + version + ID), parsing each profile's `extensions.json` and excluding built-in/system add-ons

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Codex plugins/extensions & skills (v1) | No plugin or skills system exists in the installed Codex version (v0.46.0) — MCP-only. Tracked as v2 CDX-02. |
| Gemini CLI skills/agents | Gemini has no native skills concept |
| MCP server env / headers / tokens / auth URLs | Security: catalog is git-pushed; capturing credentials would leak them into permanent history (enforced by FMT-03) |
| Restore / reinstall automation from a catalog | This milestone catalogs only; restoration is a possible future milestone |
| Catalog diffing / change reports over time | Valuable but a separate milestone |
| Cross-platform support (Linux / Windows) | Tool is macOS/Zsh-only by design |
| JSON / HTML output formats | Output stays plain-text sectioned to preserve one restorable snapshot |
| Browsers/editors beyond those listed (Safari, Edge, Brave, Zed, etc.) | Not requested |
| Refactoring existing script architecture (globals-as-parameters) | Bolt new collectors onto existing conventions; no refactor this milestone |
