# Requirements: Mac Software List Generator — v1.0.0 Python Port & Distribution

**Defined:** 2026-06-14
**Core Value:** A single run produces one complete, restorable snapshot of a machine's software *and* tooling extensions — accurate enough to rebuild the environment from, degrading gracefully when any source isn't installed.

**Milestone framing:** Re-implement the working ~2,500-line `update-list.sh` as a modular Python package at **byte-for-byte output parity**, distribute it as a single-file `.pyz` zipapp, and run it against a user-configured **external** catalog repo (app repo separated from catalog repo). The zsh script stays **completely untouched** and serves as the parity reference. Zero third-party runtime dependencies; Python 3.11+ floor; macOS-only.

## v1 Requirements

Requirements for the v1.0.0 release. Each maps to a roadmap phase.

### Packaging & Stack (PKG)

- [x] **PKG-01**: The tool is a modular Python package (core, CLI, config, and one module per collector) with **zero third-party runtime dependencies** (standard library only)
- [x] **PKG-02**: The tool targets Python **3.11+** (uses stdlib `tomllib`) and fails fast with a clear, actionable message on an older or missing `python3` — it must never hang on the macOS Command Line Tools install dialog
- [x] **PKG-03**: The tool builds into a single-file **`.pyz` zipapp** with an `#!/usr/bin/env python3` shebang that runs correctly from any directory (never resolving the catalog repo from `__file__`)
- [x] **PKG-05**: The tool supports `--version` and `--help`

### Config & Repo Separation (CFG)

- [x] **CFG-01**: Catalog-repo location is resolved by precedence: **CLI flag > environment variable > config file > clear error** (no silent default)
- [x] **CFG-02**: Configuration is stored at `${XDG_CONFIG_HOME:-$HOME/.config}/maccat/config.toml` (XDG convention, not `~/Library/Application Support`)
- [x] **CFG-03**: A `--catalog-dir` flag overrides the configured location at runtime **without** writing back to the config file
- [x] **CFG-04**: A `config init` subcommand interactively captures and validates the catalog-repo path and writes the config; a `config show` subcommand prints the resolved effective configuration
- [x] **CFG-05**: The app repo is separated from the catalog repo — the tool operates on the user-pointed external catalog repo and never assumes the catalog lives next to the executable
- [x] **CFG-06**: The tool fails fast with a clear error when the catalog dir is missing or is not a git repo, and warns-and-continues when the git remote is absent

### Catalog Generation Parity (CAT)

- [x] **CAT-01**: All current collectors are re-implemented — Homebrew formulae/casks, Mac App Store (`mas`), Setapp, web `/Applications`, the four AI CLIs (Claude Code, Codex, OpenCode, Gemini), VS Code, Cursor, Chrome, and Firefox (all profiles)
- [x] **CAT-02**: Output uses the exact `name (version) [id]` line format and the FMT-01 degradation rules (id-as-name, bracket suppression, empty-field handling)
- [x] **CAT-03**: Output ordering is produced by shelling out to `LC_ALL=C sort -f -u` (and `sort -V` for Chrome version-directory selection) — never Python's `sorted()`
- [x] **CAT-04**: Chrome `__MSG_…__` and VS Code `%nls%` placeholder names are resolved exactly as the zsh tool does (with the same ID/displayName fallbacks)
- [x] **CAT-05**: No secrets are ever written to the catalog — MCP entries emit name + transport only (never env/headers/args/command/url)
- [x] **CAT-06**: Graceful degradation is preserved — an absent source/tool writes `(none found)` / a fallback message and never aborts the run
- [x] **CAT-07**: Section titles, order, and `------` separators are byte-identical to the zsh catalog

### Operational Parity (OPS)

- [x] **OPS-01**: The always-shown computer-folder selection menu (existing folders + create-new + Quit, remembered folder as Enter default) is reproduced, TTY-guarded
- [x] **OPS-02**: `--computer "Name"` with `--personal`/`--office`/`--machine` aliases and mutual-exclusion is reproduced
- [x] **OPS-03**: Newest-per-machine retention is reproduced (two-pass per-host max-timestamp; tied-newest kept; unparseable-timestamp files skipped, never moved/deleted)
- [x] **OPS-04**: Archive prune at N days is reproduced with the `--archive-days N` flag (or prompt), and the correct **generate-then-sweep** ordering (the just-written catalog is never archived)
- [x] **OPS-05**: The `machine-labels.tsv` hostname→folder map is read/written with atomic (tmp + rename) writes, preserving comments/blank lines
- [x] **OPS-06**: Git pull → generate → commit/push runs as a single commit syncing adds/moves/deletes; `--no-commit` skips git while disk operations still run
- [x] **OPS-07**: `--rename` renames a computer folder (+ its archive) with an opt-out-gated `[old]→[new]` filename rewrite, a **hard refuse-clobber** guard, and a single-commit map update
- [x] **OPS-08**: Interactive flows are safe — non-TTY runs never hang (fail-fast guards), EOF/Ctrl-D exits cleanly, and invalid input re-prompts

### Parity & Safety Testing (TEST)

- [x] **TEST-01**: A golden-output parity test suite asserts the Python catalog section bodies are **byte-identical** to the zsh script's output
- [x] **TEST-02**: Volatile fields (14-digit timestamp, hostname/`[label]`) are normalized/stripped before comparison; stable fields (every item line, section order, separators, sort order, `(none found)`) are asserted exactly
- [x] **TEST-03**: Golden reference fixtures are generated by running the untouched zsh script in a **disposable clone / `mktemp` fixture** (pty-driven for interactive flows) — never against the real catalog repo; destructive-op safety invariants (retention ordering, tied-newest, unparseable-skip, refuse-clobber) are covered by isolated-fixture tests
- [x] **TEST-04**: `update-list.sh` remains untouched throughout the milestone and is preserved as the parity reference implementation

## Out of Scope

Explicitly excluded. Documented to prevent scope creep. (Anti-features surfaced in research.)

| Feature | Reason |
|---------|--------|
| Cross-platform support (Linux/Windows) | macOS-only by design — `/Applications`, macOS browser paths, `plistlib`/`mas` are macOS-specific; the tool detects and exits on non-macOS |
| Plugin/extension API for collectors | Personal/small tool — new collectors are added directly to the package, not via a plugin system |
| TUI / curses interface | The numbered-menu flow is tested and correct; a TUI adds complexity without value |
| JSON / HTML output formats | Output stays plain-text sectioned to preserve the one diffable, restorable snapshot |
| Telemetry / analytics | Trust-destroying for a developer tool whose users read the source |
| Automated restore/reinstall execution | Genuinely dangerous; a possible future milestone generates a *reviewable* script, never auto-executes |
| Named config profiles | Speculative — `--catalog-dir` covers the one-off override case |
| Refactoring/altering `update-list.sh` | The zsh script is the untouched parity reference; it is not modified or deleted this milestone |
| New collectors beyond current parity (Safari, Edge, Brave, Zed, etc.; CHR-02/FF-02 enabled-state; CDX-02 Codex plugins) | This milestone is parity-only; new sources are future work |
