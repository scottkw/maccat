## Cross-Phase Integration

The full chain is wired and verified end-to-end by the integration checker:
`maccat reinstall [--from PATH | --computer NAME]` → root cli.py two-point dispatch (gen path
untouched) → run_reinstall → resolve_catalog_path → parse_catalog → emit_reinstall_script →
write reinstall.sh at 0o644 + print absolute path (never subprocess-run). The mas numeric id
preserved in Phase 24 flows through the parser into Phase 25's `mas install <id>` line. 0
orphaned exports, 0 missing connections, 2/2 E2E flows complete.

An end-to-end smoke test confirmed `maccat reinstall --from <fixture>` produces a 0o644
`reinstall.sh` that passes `bash -n`, with the correct shebang + provenance header, universal
brew guard, brace-group-guarded mas/editor installs, id-less mas → checklist, and Setapp/Chrome
→ manual checklist.

## Code Review

A code-review + auto-fix loop ran on every phase and converged clean each time. Notable real
defects caught and fixed before completion:
- Phase 24: mas subprocess could abort the whole catalog run (WR-01, warn-and-continue restored).
- Phase 25: **BLOCKER** — bare `mas install` aborts the script under `set -Eeuo pipefail` on the
  routine already-installed exit; fixed with brace-group `{ install || echo WARN; }` guards and
  mutation-verified runtime execution tests for brew/mas/editor install-failure paths.
- Phase 26: `maccat reinstall --computer NAME` failed (flag was top-level only) — fixed (RST-02);
  unreadable `--from` now fails cleanly; picker `--computer` no longer mutates the catalog repo.
