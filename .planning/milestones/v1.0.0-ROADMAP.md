## Phase Details

### Phase 13: Package Foundation + Output Format
**Goal**: A runnable Python package skeleton exists with the complete output format layer — every downstream collector and test can be built on a stable, byte-verified foundation
**Depends on**: Nothing (first phase of milestone)
**Requirements**: PKG-01, PKG-02, CAT-02, CAT-03, CAT-04, CAT-07
**Success Criteria** (what must be TRUE):
  1. `src/maccat/` imports cleanly with zero third-party runtime deps; `python -c "import maccat"` succeeds
  2. `flush_section()` shells out to `LC_ALL=C sort -f -u` and produces byte-identical output to the equivalent zsh call for mixed-case, non-ASCII, and punctuation-containing names — never Python `sorted()`
  3. `CatalogWriter` writes section headers, item lines, and separators that are byte-identical to the zsh `write_section` + `emit_item` pattern (verified by `xxd` at section boundaries)
  4. Chrome `__MSG_…__` and VS Code `%nls%` placeholder names resolve correctly using the same ID/displayName fallback logic as the zsh script
  5. Running `python3 --version` below 3.11 prints a clear, actionable error and exits — it never hangs on the macOS CLT install dialog
**Plans**: 3 plans
Plans:
- [x] 13-01-PLAN.md — Package skeleton: pyproject.toml, __init__.py, __main__.py version guard, dev venv (PKG-01, PKG-02)
- [x] 13-02-PLAN.md — Format layer: format.py (emit_item, flush_section, version_sort_tail), writer.py (CatalogWriter), byte-level tests (CAT-02, CAT-03, CAT-07)
- [x] 13-03-PLAN.md — Name helpers: json_io.py, chrome_name.py, vsc_name.py, test_helpers.py, golden scaffold (CAT-04)

### Phase 14: Config, Identity & Retention
**Goal**: The tool resolves its catalog repo from config or flag, presents the correct computer-folder selection menu, manages identity/rename, and runs retention/prune — all without touching a live catalog repo
**Depends on**: Phase 13
**Requirements**: CFG-01, CFG-02, CFG-03, CFG-04, CFG-05, CFG-06, OPS-01, OPS-02, OPS-03, OPS-04, OPS-05, OPS-07, OPS-08
**Success Criteria** (what must be TRUE):
  1. `config init` writes `~/.config/maccat/config.toml` with a validated catalog-repo path; `config show` prints the resolved effective config including the precedence winner (flag > env > file > error)
  2. The computer-folder selection menu shows existing folders + create-new + Quit, remembers the previous folder as the Enter default, and never hangs in a non-TTY context (piped input fails fast with a clear error)
  3. `--computer "Name"` with `--personal`/`--office`/`--machine` aliases works non-interactively; mutual-exclusion error fires when more than one selecting flag is passed
  4. `retain_newest_per_host` keeps ALL files tied for newest (two-pass, not `max()`); `prune_old_archives` skips (never deletes) files with unparseable timestamps; `--archive-days N` controls the cutoff
  5. `rename_machine` hard refuses to clobber an existing folder name and exits cleanly; atomic `machine-labels.tsv` writes preserve existing comments and blank lines; Ctrl-D at any prompt exits cleanly without traceback or infinite loop
**Plans**: 4 plans
Plans:
- [x] 14-01-PLAN.md — naming.py (CatalogFilename, parse_catalog_filename, make_catalog_filename) + test_naming.py + conftest.py fixtures (git_repo, catalog_repo) (OPS-03, OPS-07)
- [x] 14-02-PLAN.md — retention.py TDD (retain_newest_per_host, prune_old_archives, cutoff_yyyymmdd) + test_retention.py (OPS-03, OPS-04)
- [x] 14-03-PLAN.md — identity.py (resolve_computer_selection flag/mutual-exclusion resolver, validate_computer_name, select_computer, upsert_machine_label, rename_machine) + test_identity.py (OPS-01, OPS-02, OPS-05, OPS-07, OPS-08)
- [x] 14-04-PLAN.md — config.py (Config, load_config, resolve_catalog_repo, validate_catalog_repo, config_init, config_show) + test_config.py (CFG-01..06, OPS-08)

### Phase 15: Collectors
**Goal**: All 12 source collectors are implemented at byte-parity with the zsh script, degrade gracefully when the source is absent, and never emit secrets
**Depends on**: Phase 13, Phase 14
**Requirements**: CAT-01, CAT-05, CAT-06
**Success Criteria** (what must be TRUE):
  1. All 12 collectors run end-to-end: Homebrew formulae/casks, App Store (`mas`), Setapp, web `/Applications`, Claude Code, Codex, OpenCode, Gemini, VS Code, Cursor, Chrome (all profiles), Firefox (all profiles)
  2. When any optional source is absent (`mas` not installed, Chrome not installed, no Firefox profiles), the collector writes `(none found)` or the appropriate fallback message and the run completes successfully
  3. No catalog output contains secrets — grep for `token`, `Bearer`, `sk-`, `ghp_`, `key=`, `Authorization` across the full output returns zero hits
  4. Section order in the REGISTRY matches the zsh `generate_catalog` section order exactly
**Plans**: 8 plans
Plans:

- [x] 15-03-PLAN.md — SetappCollector + WebAppsCollector (filesystem raw-write, Pitfall C) (CAT-01, CAT-06)

### Phase 16: Git, CLI & Distribution
**Goal**: The tool runs end-to-end from a `.pyz` zipapp against a user-configured catalog repo, with correct generate-then-sweep ordering, git integration, and all operational flags wired
**Depends on**: Phase 14, Phase 15
**Requirements**: OPS-06, PKG-03, PKG-05
**Success Criteria** (what must be TRUE):
  1. Running `./maccat.pyz --help` and `./maccat.pyz --version` work from any directory with no `__file__`-relative path errors; `zipfile -l maccat.pyz` shows no `.so`/`.dylib` files
  2. A full run against a test catalog repo executes in the correct order: git pull → generate catalog → retain newest → prune archives → git commit/push; the just-written catalog is never archived on the same run
  3. `--no-commit` skips git while all disk operations (generate, retain, prune) still run
  4. `git add` uses `-- <pathspec>` so computer folders named with a leading dash stage correctly; `--rename` produces a single commit staging old-folder deletes, new-folder adds, and map update
**Plans**: 3 plans
Plans:
- [x] 16-01-PLAN.md — gitops.py (git_pull, git_commit_and_push, git_commit_rename) + identity.py:625 stub wire + tests/test_gitops.py (OPS-06)
- [x] 16-02-PLAN.md — cli.py (argparse + run orchestration) + __main__.py stub fill + tests/test_cli.py (PKG-05, OPS-06)
- [x] 16-03-PLAN.md — scripts/build-pyz.sh + dist/maccat.pyz build + tests/test_pyz.py (PKG-03)

### Phase 17: Parity & Safety Tests
**Goal**: The Python implementation is proven byte-identical to the zsh reference for every catalog section, and all three destructive-op safety invariants are covered by isolated-fixture tests
**Depends on**: Phase 15, Phase 16
**Requirements**: TEST-01, TEST-02, TEST-03, TEST-04
**Success Criteria** (what must be TRUE):
  1. Golden-output parity tests pass: Python catalog section bodies are byte-identical to zsh output after volatile-field normalization (14-digit timestamp, `[label]` hostname stripped); every item line, section order, separator, sort order, and `(none found)` is asserted exactly
  2. `update-list.sh` is present, unmodified, and passes `zsh -n` at the end of the milestone — it is the parity reference and has never been touched
  3. Isolated-fixture tests cover the three destructive-op safety invariants: (a) `prune_old_archives` skips files with unparseable timestamps; (b) `retain_newest_per_host` keeps all tied-newest files; (c) `rename_machine` hard refuses to clobber an existing folder
  4. `PYTHONHASHSEED=random` is set in CI config; parity tests pass across multiple hash seeds
**Plans**: 3 plans
Plans:
- [x] 17-01-PLAN.md — normalize.py + generate.py + --update-golden conftest + synthetic fake_home tree + generate & commit 17 golden fixtures (TEST-01, TEST-02, TEST-03)
- [x] 17-02-PLAN.md — test_golden_parity.py: parametrized 17-section parity suite with per-section fixture factories (TEST-01, TEST-02)
- [x] 17-03-PLAN.md — test_safety_invariants.py + test_update_list_integrity.py + pyproject marker + .github/workflows/ci.yml (TEST-03, TEST-04)
