# Codebase Structure

**Analysis Date:** 2026-06-12

## Directory Layout

```
mac-software-list/
├── update-list.sh              # Main script — only executable code in the repo
├── README.md                   # Usage documentation
├── personal/                   # Catalogs generated from personal machines
│   ├── archive/                # Catalogs older than 60 days (auto-moved)
│   │   └── mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt
│   └── mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt
├── office/                     # Catalogs generated from office/work machines
│   ├── archive/                # Catalogs older than 60 days (auto-moved)
│   │   └── mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt
│   └── mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt
└── .planning/                  # GSD planning documents (not committed by script)
    └── codebase/
        ├── ARCHITECTURE.md
        └── STRUCTURE.md
```

## Directory Purposes

**`personal/`:**
- Purpose: Holds software catalogs from personal macOS machines
- Contains: Timestamped `.txt` catalog files, one per script run
- Key files: Most-recent `mac-software-list-[computer-one.local]-*.txt`

**`personal/archive/`:**
- Purpose: Long-term storage for personal catalogs older than 60 days
- Generated by: `archive_old_catalogs "personal"` inside `update-list.sh`
- Key files: All historical personal catalogs beyond the 60-day window

**`office/`:**
- Purpose: Holds software catalogs from office/work macOS machines
- Contains: Timestamped `.txt` catalog files, one per script run
- Key files: Most-recent `mac-software-list-[computer-two.local]-*.txt`

**`office/archive/`:**
- Purpose: Long-term storage for office catalogs older than 60 days
- Generated by: `archive_old_catalogs "office"` inside `update-list.sh`

**`.planning/codebase/`:**
- Purpose: GSD codebase map documents
- Generated: Yes (by GSD mapper)
- Committed: Not managed by `update-list.sh`; committed manually

## Key File Locations

**Entry Point:**
- `update-list.sh`: The single executable — all logic lives here

**Documentation:**
- `README.md`: User-facing usage guide, prerequisites, examples

**Generated Output:**
- `personal/mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt`: Active personal catalogs
- `office/mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt`: Active office catalogs
- `personal/archive/mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt`: Archived personal catalogs
- `office/archive/mac-software-list-[hostname]-YYYYMMDDHHMMSS.txt`: Archived office catalogs

## Naming Conventions

**Catalog files:**
- Pattern: `mac-software-list-[<hostname>]-<YYYYMMDDHHMMSS>.txt`
- Hostname is wrapped in literal square brackets `[` and `]`
- Timestamp is 14 digits: year (4) + month (2) + day (2) + hour (2) + minute (2) + second (2)
- Examples:
  - `mac-software-list-[computer-one.local]-20260612130331.txt`
  - `mac-software-list-[computer-two.local]-20260607205427.txt`
  - `mac-software-list-[computer-two.local]-20260602071629.txt`

**Directories:**
- Two fixed top-level output directories: `personal/` and `office/`
- Each contains one fixed subdirectory: `archive/`
- Directory names are all lowercase, no hyphens

**Script:**
- `update-list.sh` — kebab-case, `.sh` extension, zsh shebang

## Catalog File Internal Structure

Each `.txt` file uses a plain-text section format:

```
[blank line]
Installed Mac Software List
------------------------------------
[blank line]
Homebrew Packages
------------------------------------
[one package per line]

App Store Applications
------------------------------------
[AppName Version per line]

Setapp Applications
------------------------------------
[AppName.app per line]

Web-installed Applications
------------------------------------
[AppName.app per line]
```

Section headers are separated by `------------------------------------` (36 dashes), written by the `write_section` function in `update-list.sh` (line 254).

## Where to Add New Code

**New data collection source:**
- Add a new section block inside `generate_catalog` in `update-list.sh` (after line 335)
- Call `write_section "Section Title"` first, then append collected data to `$OUTPUT_FILE`
- Guard with a `command -v tool` or `[[ -d path ]]` check so the script degrades gracefully

**New CLI flag:**
- Add a `case` arm in `parse_arguments` (around line 100–120 in `update-list.sh`)
- Set a global variable; reference it later in the main block or relevant function

**New target location (e.g., `work-laptop/`):**
- Create the directory at repo root
- Add it as a valid value in `parse_arguments` and `get_target_location` in `update-list.sh`
- The archive logic in `archive_old_catalogs` is parameterized and will work automatically

**New catalog section formatting:**
- The `write_section` function (line 254 in `update-list.sh`) handles all headers
- To change formatting globally, edit only that function

## Special Directories

**`personal/archive/` and `office/archive/`:**
- Purpose: Auto-archiving destination for catalogs older than 60 days
- Generated: Yes — created by `archive_old_catalogs` on first run if absent
- Committed: Yes — archived files are staged and committed by `git_commit_and_push`

**`.planning/`:**
- Purpose: GSD workflow planning artifacts
- Generated: Yes — by GSD mapper/planner agents
- Committed: Not managed by `update-list.sh`
