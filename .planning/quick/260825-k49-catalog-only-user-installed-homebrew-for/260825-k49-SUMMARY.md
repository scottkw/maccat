# Quick Task 260825-k49: Catalog Only User-Installed Homebrew Formulae Summary

The `Homebrew Packages` section now lists only top-level formulae by intersecting the
`brew list --formula --versions` output with the `brew leaves` name set, matching on the
bare formula name so tap-installed leaves survive; casks are untouched and an unusable
`brew leaves` degrades to the full formula list plus a stderr warning.

## What Was Built

`HomebrewCollector.collect()` issues three fixed-order subprocess calls —
`brew list --formula --versions`, `brew leaves`, `brew list --cask --versions` — and uses
the middle one purely as a name filter over the first. The versioned list remains the
source of both line content and ordering, so the existing `name (version...)` shape
(VER-01/VER-02) and `brew`'s ordering (VER-06) are preserved unchanged. Casks bypass the
filter entirely, since `brew leaves` covers formulae only.

When the leaf set comes back empty — whether from a non-zero exit or empty stdout, which
`_run` collapses to the same `[]` — and formulae are present, the filter is skipped and a
single `  WARNING:` line goes to stderr. No warning fires when no formulae are installed,
because the filter is a no-op there.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Tap-qualified `brew leaves` names never matched the versioned list**

- **Found during:** Task 2 verification (the plan's step-3 real-machine smoke check)
- **Issue:** The plan specified membership testing the first whitespace token of each
  versioned line against the raw `brew leaves` token. On a real machine `brew leaves`
  prints third-party tap formulae **fully qualified** — `auth0/auth0-cli/auth0`,
  `microsoft/mssql-release/msodbcsql18` — while `brew list --formula --versions` prints
  the bare name `auth0`. The naive equality test therefore dropped every tap-installed
  leaf, which are precisely the formulae a user most deliberately installed. The smoke
  check showed 120 items against a predicted 126; `comm` against the two name lists
  identified exactly 5 qualified leaves with no bare-name match, and 84 − 5 + 41 = 120
  accounted for the gap precisely.
- **Fix:** Build `leaf_names` from `tokens[0].rsplit("/", 1)[-1]`, comparing on the last
  path segment. A bare-name collision between a tap formula and a same-named core formula
  would include the core one even if not a leaf — over-inclusion, the same safe
  degradation direction the plan already chose for T-k49-03.
- **Files modified:** `src/maccat/collectors/homebrew.py`, `tests/collectors/test_homebrew.py`
  (added `test_tap_qualified_leaf_matches_bare_formula_name`)
- **Commit:** `a3e24d5`
- **Post-fix:** 125 items, matching the predicted 84 + 41 exactly.
